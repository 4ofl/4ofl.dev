socket-level anti-ssrf

Defeating DNS rebinding and TOCTOU attacks in Node.js by validating and pinning remote IP addresses during the TCP handshake.

2026-10-24 · 7 min read · systems & network security

When building network-facing tools—like Discord link unfurlers, web sentinels, or automated screenshot daemons—your application must fetch arbitrary URLs supplied by untrusted users. If you simply pass that URL into fetch() or axios.get(), you introduce a catastrophic attack vector: Server-Side Request Forgery (SSRF).

An attacker points your server at http://169.254.169.254/latest/meta-data/ to steal cloud IAM credentials, or probes http://127.0.0.1:6379 to access internal database sockets. But even when developers attempt to validate the URL, almost all naive implementations are completely broken by design.

The Flaw: Time-of-Check to Time-of-Use (TOCTOU)

The typical naive defense looks something like this: 

// NAIVE IMPLEMENTATION (VULNERABLE TO DNS REBINDING)
async function fetchSafeUrl(rawUrl) {
  const parsed = new URL(rawUrl);
  
  // Step 1: Resolve DNS to verify IP
  const { address } = await dns.promises.lookup(parsed.hostname);
  if (isPrivateIP(address)) {
    throw new Error("Access denied: Private IP range");
  }

  // Step 2: Fetch the URL
  return await fetch(rawUrl); 
}

This code creates a critical race condition known as DNS Rebinding:

  1. The attacker controls an authoritative nameserver for rebind.attacker.com with a DNS TTL of 0 seconds.
  2. In Step 1, your application resolves the domain. The attacker’s server returns a benign public IP (e.g. 93.184.216.34). isPrivateIP() returns false. Validation passes.
  3. In Step 2, fetch() initiates a connection. Because the TTL was 0 seconds (or expired), Node’s internal HTTP client queries DNS a second time.
  4. The attacker’s nameserver now responds with 127.0.0.1 or 169.254.169.254.
  5. Node happily connects the TCP socket directly to your internal network or localhost loopback interface.
Core Invariant Any architecture that separates the IP validation step from the socket connection step is fundamentally vulnerable to DNS rebinding. Validation and connection must be an atomic operation.

Why URL Rewriting Breaks TLS SNI

Some developers attempt to solve this by resolving the IP first, then rewriting the request URL: 

// Rewriting hostname to raw IP: breaks TLS certificate verification
fetch(`https://${resolvedIp}/path`, { headers: { Host: parsed.hostname } });

While this ensures the connection hits the checked IP, it catastrophically breaks modern HTTPS:

  • SNI Failure: The TLS handshake passes resolvedIp instead of example.com in the Server Name Indication (SNI) extension. Cloudflare, AWS CloudFront, and multi-tenant servers will reject the connection or serve an invalid default certificate.
  • Certificate SAN Mismatch: Node’s TLS engine compares the certificate against the IP address in the URL, throwing an ERR_TLS_CERT_ALTNAME_INVALID error.

The Solution: Overriding the Native Agent Lookup Hook

In Node.js, both http.Agent and https.Agent expose a low-level option: lookup. This option overrides the default dns.lookup function used by Node's internal net.createConnection() immediately prior to dialing the TCP socket.

By intercepting this hook, we can:

  1. Resolve all IPv4 and IPv6 records for the hostname.
  2. Inspect every returned IP against a strict blocklist (RFC 1918, CGNAT, loopback, link-local, AWS/GCP metadata).
  3. Select the first safe IP and pass it directly to the socket connection routine.
  4. Preserve the original hostname for HTTP headers, TLS SNI negotiation, and certificate verification.

Production Implementation

import http from "node:http";
import https from "node:https";
import dns from "node:dns";
import net from "node:net";

// Strict CIDR & Range verification
function isRestrictedIP(ip) {
  if (net.isIPv4(ip)) {
    const parts = ip.split(".").map(Number);
    // 0.0.0.0/8 (Current network)
    if (parts[0] === 0) return true;
    // 10.0.0.0/8 (Private)
    if (parts[0] === 10) return true;
    // 127.0.0.0/8 (Loopback)
    if (parts[0] === 127) return true;
    // 169.254.0.0/16 (Link-local & Cloud Metadata)
    if (parts[0] === 169 && parts[1] === 254) return true;
    // 172.16.0.0/12 (Private)
    if (parts[0] === 172 && parts[1] >= 16 && parts[1] <= 31) return true;
    // 192.168.0.0/16 (Private)
    if (parts[0] === 192 && parts[1] === 168) return true;
    // 100.64.0.0/10 (Carrier-Grade NAT)
    if (parts[0] === 100 && parts[1] >= 64 && parts[1] <= 127) return true;
    return false;
  }

  if (net.isIPv6(ip)) {
    const normalized = ip.toLowerCase();
    // ::1 (Loopback)
    if (normalized === "::1" || normalized === "::") return true;
    // fe80::/10 (Link-local)
    if (normalized.startsWith("fe8") || normalized.startsWith("fe9") || 
        normalized.startsWith("fea") || normalized.startsWith("feb")) return true;
    // fc00::/7 & fd00::/8 (Unique Local Address)
    if (normalized.startsWith("fc") || normalized.startsWith("fd")) return true;
    // IPv4-mapped IPv6 (::ffff:127.0.0.1)
    if (normalized.includes("::ffff:")) {
      const v4Part = normalized.split("::ffff:")[1];
      if (net.isIPv4(v4Part)) return isRestrictedIP(v4Part);
    }
    return false;
  }

  return true; // Reject unparseable address formats
}

function createSafeLookup() {
  return function safeLookup(hostname, options, callback) {
    dns.lookup(hostname, { all: true }, (err, addresses) => {
      if (err) return callback(err);

      // Verify EVERY resolved address. If an attacker's domain resolves to
      // [1.1.1.1, 127.0.0.1], the query must be immediately aborted.
      for (const { address } of addresses) {
        if (isRestrictedIP(address)) {
          return callback(new Error(`SSRF blocked: ${hostname} resolved to restricted IP ${address}`));
        }
      }

      // Pin the connection to the first verified IP
      const selected = addresses[0];
      if (options.all) {
        callback(null, [selected]);
      } else {
        callback(null, selected.address, selected.family);
      }
    });
  };
}

// Configured HTTP/HTTPS agents with pinned socket lookup
export const safeHttpAgent = new http.Agent({
  lookup: createSafeLookup(),
  keepAlive: false,
  timeout: 5000,
});

export const safeHttpsAgent = new https.Agent({
  lookup: createSafeLookup(),
  keepAlive: false,
  timeout: 5000,
});

Defense in Depth: The 10MB Streaming Cap

Preventing SSRF is only half the battle. Once an attacker realizes internal network probing is blocked, they will attempt denial of service through memory exhaustion:

  • Streaming an infinite byte stream (e.g., /dev/urandom over HTTP).
  • Gzip decompression bombs (10MB compressed file expanding to 50GB in memory).

In the June production runtime, all outbound requests pipe through a strict byte-counting Transform stream that destroys the socket the instant response payloads exceed 10 MB: 

import { Transform } from "node:stream";

export function createSizeCapStream(maxBytes = 10 * 1024 * 1024) {
  let bytesReceived = 0;
  return new Transform({
    transform(chunk, encoding, callback) {
      bytesReceived += chunk.length;
      if (bytesReceived > maxBytes) {
        const err = new Error(`Payload exceeded security limit of ${maxBytes} bytes`);
        this.destroy(err);
        return callback(err);
      }
      callback(null, chunk);
    },
  });
}

Summary

Reliable security software does not rely on regex filters or application-level string checks. By moving validation directly into the Node.js socket transport layer:

  • DNS rebinding TOCTOU attacks are mathematically impossible because the validated IP is the exact IP the socket connects to.
  • TLS SNI and certificate validation remain completely standard and unbroken.
  • IPv4-mapped IPv6 bypasses and CGNAT edge-cases are stopped before any bytes hit the wire.
