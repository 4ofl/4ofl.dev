what broke

Zombie Gateway Sockets: Discord’s Gateway WebSocket drops into dead TCP connections without transmitting a close frame. The socket looks connected, but no traffic arrives. June monitors heartbeat acknowledgments with jittered intervals; if an interval elapses with no acknowledgment, the client immediately calls socket.destroy() and resumes the session. When clustering across multiple shards, spawns are staggered by 5,500ms to eliminate Discord identify rate limits.

Outbound SSRF & DNS Rebinding (TOCTOU): Diagnostic utilities (like /screenshot and the /watch sentinel) accept arbitrary user URLs. Naive HTTP clients re-resolve DNS on connect, allowing attackers to pass a validation check with a public IP and rebind to 127.0.0.1 or cloud metadata endpoints. June overrides Node's native transport lookup agent hook, validating all IPv4/IPv6 addresses against private and CGNAT blocks, and pins the TCP socket directly to the pre-validated IP address with a 10MB streaming byte cap.

ReDoS Event-Loop Starvation & The "0" Guild Sentinel: Malicious regular expressions in user utilities can starve Node's single-threaded event loop, delaying gateway heartbeats until Discord evicts the client. Regex execution is sandboxed in isolated worker_threads backed by a 500ms software watchdog timer. Additionally, when Discord introduced user-installable apps encoding DM interactions with a "0" guild sentinel, June introduced specificGuildOwner() to decouple user vs guild whitelisting and prevent erroneous access rejections.
